# Nap v1 Progress

**v1 is complete and deployed** — <https://nap-tawny.vercel.app>, with the API on Railway at
<https://nap-api-production.up.railway.app>. Every M0–M5 task is `DONE`; how the deployment is
put together, and the one rule it rests on (never more than one API instance), is in
`docs/DEPLOY.md`. See T-16 below.

> **Three things to do to a working checkout**, as of F-1. Add `BETTER_AUTH_SECRET=` *and*
> `NAP_KEY_ENCRYPTION_SECRET=` to `apps/api/.env` (each `openssl rand -base64 32`; the second
> must decode to exactly 32 bytes) — the API will not boot without either. The OAuth pairs
> `GITHUB_CLIENT_ID`/`GITHUB_CLIENT_SECRET` and `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` are
> optional but each must be set together; without them that button is not offered and email
> sign-in works. Then run **`bun run db:migrate`** — `0002` adds `users.is_anonymous` and the
> `user_api_keys` table, and a database without it fails every sign-in.

> **No real runs remain outstanding.** The last of them (T-13) confirmed the prompt cache hits *and*
> that OpenRouter returns Anthropic-shaped usage rather than OpenAI-shaped. M4-5 was the third until it was built on a scripted model — the persistence
> cycle is what it asserts, and a real model would make its assertions softer rather than
> stronger. Bedrock remains blocked on AWS model access (see T-12), so the Anthropic path is
> the one to fund.

> **The API now needs an R2 bucket to boot**, as of M4-3 — `R2_ACCOUNT_ID`, `R2_BUCKET`,
> `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` in `apps/api/.env`. A server that can destroy
> sandboxes but has nowhere to snapshot them is worse than one that does neither.

> **The app works end to end.** `bun run dev` serves a landing page at `/` for visitors who have
> no account — the pitch, the morphing card and the two ways in. Anybody signed in is sent to
> `/dashboard`: a rail of scopes and recents, a greeting, and the lit box they type into, with
> their projects as a searchable grid underneath. Typing a prompt there creates a project and
> sends that prompt as its first turn; opening an existing one goes to `/p/<projectId>`, where a
> message streams a turn, shows the preview and lists the files. Projects can be created, closed
> (snapshotted away) and deleted (rows *and* R2 objects) from the grid, and a project that has
> been put away is started back up from the **Resume** button in its preview pane — no model call, so looking at what you built costs a sandbox and nothing
> else. The API spends money: it creates E2B sandboxes and calls the model through
> OpenRouter, defaulting to `openai/gpt-5.6-luna` at `medium` — see `apps/api/.env.example`.

> Before any M2 work, read the `claude-api` skill rather than answering from memory —
> `CLAUDE.md` explains why that milestone is the one where a stale recollection costs most.

> **Which model to point at.** Everything goes through OpenRouter. Debug on
> `openai/gpt-5.6-luna` — ~$0.10/$0.60 per MTok, so the loop can be run over and over — and
> record anything anyone will watch on `anthropic/claude-opus-5`. Crossing vendors is safe
> *specifically* because OpenRouter's native Anthropic endpoint normalises the two things that
> would otherwise break silently: the usage shape and the one-message tool-result batching.
> Both were measured, not assumed. See the model-split gotcha in `CLAUDE.md`.
> **Actionable since M2-9:** `ClaudeProvider` takes `model`, `effort` and `maxTokens`;
> `DEFAULT_MODEL_CONFIG` still holds the Opus/`xhigh` defaults, and `bun run harness --real`
> overrides them with the cheap ones.

Four mutations observed failing: treating absent as a result, skipping renormalisation, dropping failed checks from a category's denominator, and rounding each effective weight on its own. **The review found the recorded weights could sum to 100.1**, because rounding each share independently gains or loses a tenth (55.6 + 27.8 + 16.7). That is not cosmetic: a reader recomputing the overall from the report would disagree with it, and `docs/adr/0002` has `compare` refuse two runs whose effective vectors differ, which would have become a comparison of rounding artefacts. Weights are now apportioned by largest remainder to sum to exactly 100, and the overall is computed **from the recorded numbers** rather than the exact shares — so a report is internally consistent and its headline is reproducible by hand rather than to within a rounding error. Assert on tenths, not on the float sum: 33.3 + 33.4 + 33.3 is 99.99999999999999 in binary.
